# 0903 원가 안전 보완

## 처리 순서와 결과

1. 실제 계산 없이 승인되던 기존 실행 함수를 차단하고, 기존 미완성 미리보기를 사용 불가로 변경.
2. 원본 스냅샷을 대상으로 FIFO를 계산하는 순수 DB 함수 구현. 미리보기는 실재고·원가층·출고 배정을 변경하지 않음.
3. 출고별 기존/변경 원가층·수량·단가·원가 합계를 저장하고 화면에 표시. 미확정과 확정 0원을 구분.
4. 미리보기 → 검토 확인 → 승인 → 적용 단계 분리. 승인 및 적용 시 원본 스냅샷 재검사. 적용은 저장된 배정만 한 트랜잭션으로 반영.
5. 원가층 테이블 공통 보호 트리거 추가. 이미 사용된 층의 단가·출처·품명 변경과 삭제를 차단. 입고 수량은 사용량 이하로 줄일 수 없음. 미사용 입고일 변경은 원가 이벤트 날짜에 반영.
6. 일반 서비스 출고를 공통 FIFO에 연결. 업체 교환출고도 실제 FIFO 배정을 A/S 기록에 연결. 재고 밖 매장제품 A/S는 출고·삭제 때 재고를 증감하지 않음.
7. 입고 재호출 시 원가층 ID·확정 단가 유지. 결제정보만 수정하거나 다른 출고 행을 수정해도 영향 없는 배정 유지.
8. 원가 연결점검에 무결성 조회와 과거 서비스 누락 목록 추가. 새 서비스 출고 원가는 재고변동에 표시하고 A/S 원가 조회는 마스터만 허용.
9. 출고 이력 추가의 품목 검색에서 빠진 실재고 조회 복구. 검색된 품목만 한 번에 조회하고 `재고 N개` 표시. 목록을 연 동안 15초마다 갱신하며 조회 실패를 0개로 표시하지 않고 재시도 제공.
10. 과거 서비스에 `앞뒤 원가 / 연결 수정` 추가. 같은 품목의 이전·이후 각 5개 원가 기록과 입고 출처, 수동 소진의 단가·연결 가능 수량 표시. 기존 소진 수량을 나눠 연결·수정·해제할 수 있으며 원가층을 다시 차감하지 않는다.
11. 연결은 마스터만 미리보기 확인 후 적용하고 변경 전후 출처·단가·수량·사유를 감사 기록에 보존. 출고일 이후 입고, 중복 사용, 수량 불일치, 오래된 스냅샷을 차단. 연결된 출고 품목과 소진 원본은 연결 해제 전 변경 차단. 결제 메모만 수정해도 이중 차감하지 않는다.

## 보존 규칙 / 적용 범위

- 원가 재배정은 실재고 수량을 변경하지 않는다. 사용자가 입고 수량을 정정하는 경우에만 그 차이를 실제 재고와 해당 원가층 잔량에 함께 반영한다.
- 원가층의 FIFO 대기열 순서를 유지하고, 출고일 이후 입고는 사용하지 않는다. 기존 수동 우선출고 순서를 임의로 바꾸지 않는다.
- 단일 품목 재배정에서는 수동 소진·원복, A/S·교환, 반품 원본 출고, 정산비용과 연결된 배정을 보존하고 이유를 표시한다. 연결된 다른 품목/정산금까지 일괄 재계산하는 기능은 아니다.
- 출고에 사용된 층의 단가를 직접 고치는 경로는 차단한다. 미리보기 승인이 이 직접 수정 제한을 해제하지 않는다.
- 승인된 0원 원가층 분리는 부모 층에서 자식 층으로 이동한 수량으로 검증한다. 소진 원복 기록도 다시 차감하지 않는다.
- 과거 일반 서비스 출고에 원가 배정 기록이 없으면 원가를 추정하거나 현재 층을 재차 소진하지 않는다. 당시 원가 출처가 확인돼야 연결 가능하다.
- 기존 입고·출고·원가 데이터에 일괄 보정이나 재배정을 실행하지 않았다.

## 검증

- 전체 회귀 테스트 68개 통과. PGlite 기존 SQL·트리거·롤백 32개, 서비스 연결 16개, 기초·직접입고·시연·부분교환 보완 10개, 실제 PostgreSQL 두 세션 동시성 3개, 출고 품목 검색 5개, 정적 RPC 검사 2개.
- `npm run lint -- --max-warnings=0`, `npx tsc --noEmit`, `npm run build`, `git diff --check` 통과.
- 운영 DB 조회 RPC와 한 품목의 순수 미리보기 계산 실행 확인. 운영 승인·재배정 실행은 하지 않음.
- 운영 DB 변경 전후 재고/원가 이벤트/원가층/배정 기록 지문 동일 확인. 확인 시 재고 행 510개, 총 수량 3,746개, 원가 이벤트 4,185개.
- 재고 추적 대상 잔량, 원가층 사용량, 출고 배정 수량, 출고 원가 합계 불일치 각각 0건.
- 과거 서비스 원가 기록 누락 41줄은 별도 목록으로 남김. 데이터 오류로 단정하거나 금액을 임의 입력하지 않음.
- 마스터 로그인 후 원가 연결점검 → 서비스 목록 → 앞뒤 원가/소진 후보 조회 → 수량·사유 입력 → 변경 내용 확인까지 실제 브라우저로 검증. 원복된 소진의 구분 표시도 확인. 운영 저장은 누르지 않았고 테스트 입력은 새로 조회로 비웠다.
- 별도 임시 PostgreSQL에서 두 세션의 동일 원가층 동시 차감, 동일 승인 건 동시 적용, 같은 소진 수량 동시 연결을 검증했다. 실제 잠금 대기를 확인한 뒤 첫 요청을 커밋하고 두 번째 요청의 거절 및 잔량·원가를 확인했다. 운영 DB는 사용하지 않았으며 임시 DB는 종료 후 삭제한다. 전체 업무 경로의 부하·교착 상태를 모두 검증했다는 의미는 아니다.
- 서비스 연결 마이그레이션 적용 전후 지문 동일: 재고 `1262e282eeedaeb172b914b6915d3804`, 원가 이벤트 `4ea4741e391e921f37b44ce865a19a23`, 원가층 `bc6250b470494ba9788582e93fa75789`, 배정 `cacc5eed14a34053d1385a131a3f35d8`. 운영 문맥 RPC에서 앞뒤 기록과 소진 후보 조회 확인. 실제 연결 저장은 실행하지 않음.

## 남아 있는 제한

- 사용자의 추정 연결 요청에 따라 41줄 중 14줄(원가 49,620원)을 실제 소진 기록에 연결했다. 주변 판매 단가와 유효 소진 단가가 일치하고 수량이 충분한 건만 처리했다. 추정임을 감사 사유에 기록했으며 원본 스냅샷 변경 시 전체 취소, 재고·원가 원본 지문 불변 검증을 수행했다. 나머지 27줄은 단가 혼재·출처 없음·수량 부족으로 미연결 유지. 상세는 `service-cost-links-0903.json` 참조.
- 이미 사용한 입고층의 단가를 정정하여 A/S·반품·정산비용까지 연쇄 갱신하는 기능은 미구현이며, 현재는 변경 차단으로 보호한다. 단일 품목 FIFO 미리보기·승인과 별도 범위다.
- 나머지 27줄은 출처 확인 전 임의로 채우지 않는다. 저장·수정·해제 및 중복 차단은 격리 DB 테스트에서 검증했다.

## 입출고 경로 보완 (20260903150000)

- 새 기초재고·직접입고 변동은 원가층을 같이 생성하며 단가가 없으면 미확정으로 유지한다. 직접입고 취소는 정확히 그 미사용 층만 소진하고, 과거 원가층 누락 또는 사용된 층은 취소를 차단한다.
- 시연 포함 입고도 전체 수량을 원가층에 넣고 시연 출고 때 한 번만 차감한다. 자동 시연 출고일은 입고일과 맞추고, 시연 비용은 실제 FIFO 배정 완료 후 그 원가로 한 번 기록한다.
- 고객 부분 교환은 원래 판매의 층별로 이미 반환된 수량을 제외한다. 원판매 수량 초과, 다른 고객·품목·미래 판매 출처를 차단하고 반복 처리에는 기존 층을 보존한다.
- 이 마이그레이션은 과거 입출고를 일괄 재작성하지 않는다. 향후 처리 경로를 보완한다.
- 서비스 편집의 기본 화면은 이전 판매 원가 / 적용 원가 / 이후 판매 원가와 단가 선택 버튼으로 단순화했다. 단가 선택 시 수량과 기본 사유를 채우며 큰 표와 수량 분할 입력은 접힌 상세 출처 안에 둔다.

읽기 전용 점검 SQL은 `tests/sql/inventory-cost-integrity.sql`, `tests/sql/inventory-cost-rpc-smoke.sql`에 있다.
